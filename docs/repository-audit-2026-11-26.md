## Security and privacy

- **P1 for reader dependency remediation.** The npm advisory scan reported seven entries across the production-classified dependency graph, including one critical and two high. The lockfile has `epubjs@0.3.93` with nested `@xmldom/xmldom@0.7.13`, and `tar@7.5.9` through the Supabase CLI path. Bloom’s committed EPUB asset matches the installed `epubjs` distribution file byte for byte, so patching requires replacing the asset as well as updating dependencies. Inventory module versions in the runtime bundle, regenerate it from a reviewed dependency tree, and keep the reader sandbox. Update the CLI dependency path separately. Advisory severity and Bloom runtime reachability need separate assessment. [Lockfile](../package-lock.json#L5348) · [Renderer loader](../src/lib/reading-reader.ts#L6) · [Reader sandbox](../src/components/reading-document-view.web.tsx#L50) · [xmldom advisory](https://github.com/advisories/GHSA-wh4c-j3r5-mjhp) · [node-tar advisory](https://github.com/advisories/GHSA-qffp-2rhf-9h96)
- **P2 for account protection on shared and lost devices.** The main mobile Supabase client persists its session in AsyncStorage, while browser and desktop use the web storage path. PIN-related credentials use SecureStore on mobile and AsyncStorage on web. PIN unlock returns a regular parent session and the device list can remove an inventory entry without revoking the device session. Use platform-protected storage where available, support real session revocation, and decide whether PIN access should expire sooner or require reauthentication for sensitive parent actions. [Main client](../src/lib/supabase.ts#L9) · [PIN storage](../src/lib/profile-switch.ts#L12) · [Unlock response](../supabase/functions/_shared/parent-pin.ts#L24) · [Device removal UI](../src/app/(app)/(tabs)/device-detail.tsx#L145)
- **P2 for the desktop native bridge.** The production CSP and main-window capability are in place. The reader opener’s native validator accepts any HTTPS origin, while the caller intends a single configured Bloom origin. Validate the expected origin and document route natively, and split the broad string-dispatched blocking command into typed operations with explicit permission and state preconditions. [CSP](../src-tauri/tauri.conf.json#L25) · [Tauri capability](../src-tauri/capabilities/default.json) · [Reader command](../src-tauri/src/lib.rs#L143) · [Blocking command](../src-tauri/src/lib.rs#L1)
- **P2 for account data controls.** The privacy screen covers social discoverability. The audited app routes and Edge Functions provide no self-service account export or deletion flow. Define retention and deletion behavior across profile records, private uploads, family links, and AI history before exposing account deletion. [Privacy screen](../src/app/(app)/privacy.tsx#L37) · [Account screen](../src/app/(app)/account.tsx)

## Performance and reliability

- **P2 for excessive read and refresh work.** The shared Bloom refresh does a settings upsert and then eight requests, including workout plans, counts, analytics and subscription data. It runs on mount and app activation. Read route focus separately reloads the module, documents, rewards, goals and 45 days of sessions. One failed dependency rejects each aggregate load. Initialize settings separately, split wallet and workout state, and load section-specific data independently with a profile-scoped cache and mutation invalidation. [Shared loader](../src/lib/bloom.ts#L181) · [Provider refresh](../src/lib/bloom-context.tsx#L49) · [Read reload](../src/components/read-module-screen.tsx#L130)
- **P2 for catalog and history growth.** The catalog fetches complete display metadata and mounts all matched cards on the library screen. Personal bests fetch up to 1,000 workout snapshots and calculate locally, so a lifetime best outside that window can disappear from the result. Use independent catalog summary and detail endpoints with paging and list virtualization. Compute historical records in the database or maintain a verified summary. [Catalog and records queries](../src/lib/bloom.ts#L141) · [Library rendering](../src/app/(app)/(tabs)/library.tsx#L100) · [API row cap](../supabase/config.toml#L18)
- **P2 for Android accessibility work.** The service processes window and text events. The window path reads accessibility roots and preferences, parses routines, and may look up the address-bar node. Profile event rate, block latency and power on a lower-end physical device. Cache compiled policies by change, and limit browser checks to relevant events without delaying hard blocks. [Event configuration](../modules/bloom-blocking/android/src/main/res/xml/bloom_blocking_accessibility_service.xml#L1) · [Event handler](../modules/bloom-blocking/android/src/main/java/expo/modules/bloomblocking/BloomAccessibilityService.kt#L64)
- **P2 for file memory and web payload.** The picker checks size when available, and upload still allocates the whole file before checking its actual byte count. Study document help downloads and extracts it again for each question, with the provider timeout starting later. Check file size before buffering when picker size is unavailable, and bound extraction time and memory. The offline web export was 7.8 MB on disk, with its two largest minified JS files about 1.2 MB and 1.1 MB before transfer compression. Measure initial-route transfer and execution before selecting what to split. [Picker and upload](../src/components/growth-document-panels.tsx#L72) · [Document help](../supabase/functions/bloom-study-document-help/index.ts#L87)

## Maintainability and regression prevention

1. **Split the growth screens by workflow.** The 1,362-line growth screen, 1,258-line panel collection and 1,104-line Read screen combine rendering, query orchestration, timers, recovery and mutation logic. Extract workflow-specific components and query or mutation hooks where they remove real duplication. Move timer and retry state out of broad presentation trees. [Growth screen](../src/components/growth-module-screen.tsx) · [Growth panels](../src/components/growth-feature-panels.tsx) · [Read screen](../src/components/read-module-screen.tsx)
2. **Give Screen Time one state contract.** Mobile Focus, macOS Focus, desktop recovery and account switching separately implement marker persistence, native access and settlement. Consolidate the reservation lifecycle and idempotency rules in shared code while keeping permission, clocks and enforcement in native adapters. Centralize the platform capability matrix used for routes and user-facing status. [Mobile flow](../src/app/(app)/focus.tsx) · [Desktop flow](../src/components/macos-focus.tsx) · [Recovery](../src/components/mac-credit-recovery.tsx) · [Sign-out cleanup](../src/lib/close-device-access.ts)
3. **Make backend contracts typechecked.** The growth data layer uses string RPC names, hand-maintained response types and casts. Generate database types from the migration schema and type the Supabase client. Consolidate repeated provider response handling and make quota, consent and request transitions testable through an injectable provider interface. [Supabase client](../src/lib/supabase.ts) · [Growth data layer](../src/lib/growth-modules.ts) · [Tutor function](../supabase/functions/bloom-study-tutor/index.ts)
4. **Put one runnable suite behind CI.** No committed CI workflow was found. The manual scripts cover useful slices, but the broad Node command exposes two suites that are absent from npm’s listed test commands. The standard SQL harness uses a synthetic baseline and only Bloom-named migrations. Pin a supported Node runtime, fix the test import resolution, run the full migration and seed chain in CI, and include RLS, dependency and platform-targeted checks. [npm scripts](../package.json#L52) · [Schema harness](../tests/run-schema.sh#L40)
5. **Tie QA evidence to build versions.** The older readiness report still describes a null desktop CSP. The current config has an explicit CSP, and current deterministic native checks pass. Keep prior results build-scoped and maintain a current support matrix with per-OS permission, reboot, revocation, browser and cross-device cases.
