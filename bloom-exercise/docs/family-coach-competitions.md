# Family profiles, coaching, and competitions

These features use the Bloom migrations through `20261113051628_bloom_clear_coach_conversation.sql` and the `bloom-provision-child`, `bloom-pair-child`, `bloom-unlock-parent`, and `bloom-coach` Supabase Edge Functions. Apply pending migrations in order to the intended project and deploy the functions before testing the app against it. Keep the Supabase service-role credential on the server only. The pairing endpoint accepts a one-use secret without a JWT; the other endpoints check the caller's session.

Parents create child profiles and issue short-lived pairing codes. A child device signs in as the child, not the parent. Parent switching uses a device-specific secret and a six-digit PIN verified on the server; it does not retain the parent's refresh token in child mode. Parent PIN unlock is unavailable for unverified, banned, anonymous, SSO, or MFA-enabled parent accounts. A parent can create a one-use code for a child to link a new, verified email account; accounts with existing activity are refused so data is not silently replaced. On iOS and Android device secrets use SecureStore; web and the macOS web shell use their local storage.

Coaching is disabled unless the server has `BLOOM_COACH_ENABLED=true`, `FIREWORKS_MODEL_VERIFIED=true`, `FIREWORKS_DATA_SHARING_APPROVED=true`, a `FIREWORKS_MODEL`, and a `FIREWORKS_API_KEY`. Child requests also require `BLOOM_MINOR_COACH_APPROVED=true`, child consent, and parent enablement, consent, and eligibility attestation. Do not set these flags or configure paid access until the selected model, data handling, child eligibility, safety evaluation, budget, and credentials have been explicitly approved. [Fireworks terms](https://fireworks.ai/terms-of-service) restrict personal information of children under 13 or the applicable digital-consent age; obtain current legal and provider guidance before enabling child requests. The local symptom and identifying-information filters are safeguards, not a complete safety or privacy evaluation.

As of November 13, 2026, Fireworks states that [open-model inference has zero data retention by default](https://fireworks.ai/product/inference). Its [October 2026 security incident update](https://fireworks.ai/security/bulletins/october-2026-security-incident-update) says the investigation is ongoing and that no impact to inference had been detected at the time of the update. Recheck the provider's current terms, incident updates, retention settings, model availability, and age suitability before enabling the integration.

Public competition management is restricted to accounts in `bloom_private.competition_admins`; the migrations do not add any administrators. A database administrator must explicitly grant a trusted account access using its Auth user ID after reviewing the intended project. The app never grants this role. Results are calculated from completed saved workouts, use display names, and can be self-reported. A timed workout that started before the event or before participation approval is excluded from active minutes because its eligible interval cannot be separated. Badges are finalized when results or the participant's badges are loaded after the event ends.

For an isolated verification run, use `BLOOM_TEST_POSTGRES_BIN=<postgres-bin-directory> bash tests/run-schema-local.sh`, `python3 tests/auth-pairing-integration.py`, and the Deno tests in `../supabase/functions/_shared`. The Auth integration uses disposable local Docker services. These checks and an app build do not replace testing sign-in, pairing, PIN switching, linking, coaching, and competition flows on supported devices against a dedicated test project. Do not use real child information in test data.

After deploying to a dedicated test project, `python3 tests/remote-family-smoke.py --project-ref <test-project-ref>` exercises the deployed pairing, parent PIN, custom exercise, child search, and private competition approval APIs. Add `--extended` to test coaching consent and privacy, paused timing, and duplicate workout scoring without calling Fireworks. Add `--convert` as well to test linking a second verified test account with no existing Bloom activity. The conversion permanently links that test account to the synthetic child profile, so the script asks for confirmation at that step.

The script requires the matching publishable configuration in `.env.notary-test.local` and prompts locally for test-account credentials. It keeps credentials and tokens in memory, signs out its sessions, and removes its temporary device PIN. It creates a synthetic family, managed child, exercise, workout, and private event; those records remain in the test project for an administrator to remove. It does not test device UI, public-event administration, or a live coaching provider.
