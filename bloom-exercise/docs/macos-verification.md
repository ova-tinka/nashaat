## Access-window expiry groundwork

The root-owned policy format can now represent a boot-bound access window while retaining its approved domains. Reconciliation temporarily removes only Bloom's marked entries during a valid window and restores them when the deadline passes, the boot changes, or a trusted clock is unavailable. Once blocking is restored, it clears the expired window from the saved policy. A daemon timer runs reconciliation without the app window. Temporary-file fixtures cover expiry, restart with the same boot, reboot, missing clock, retained rules, and timer invocation.

There is deliberately no XPC or UI operation that creates these windows yet. Server verification, binding a grant to the account and Mac user that owns the saved rules, parent-rule synchronization, and actual enablement must be wired and verified before this can grant real access. The fixtures supply synthetic policy data only; no server reservation, live hosts file, signed service, sleep/wake, or power-loss test was performed.

The saved policy can now carry an account profile and macOS user ID. Its local window-install transaction rejects a missing or mismatched owner, validates the boot-bound deadline and session ID, never extends an existing window on retry, and remembers the last completed session when it restores blocking. It persists the window before removing Bloom entries so restart reconciliation can finish an interrupted change. The fixture exercises missing policy, wrong user, wrong profile, retry, expiry and reboot using synthetic IDs and temporary files. This transaction is not exposed through XPC or the app: it must only be called after the privileged service independently verifies the server grant and binds enrollment to the verified account. No server credits or real hosts file were used.

## Read-only server verification for the broker

A new migration defines a read-only Easy-grant verifier. It requires an authenticated linked profile, session ID and matching device key, rejects other accounts and settled or abandoned sessions, and returns remaining time calculated by the database clock. It cannot create or settle a reservation. The isolated schema suite covers active, expired, wrong-device, wrong-account, settled and execution-permission cases.

The broker has a new XPC operation that first checks the signed host's macOS user against the saved policy owner, verifies the existing reservation against the server, and installs the owner-bound window only while the original boot and conservative deadline remain valid. It rechecks the saved owner when installing. Native fixtures inject synthetic grant responses and check mismatched peers, accounts, expired network delays and a boot change. The filter version is 1.1.16 for the protocol change. The app has no caller for this operation or owner-bound enrollment yet, parent-rule synchronization is incomplete, and the migration has not been applied to the hosted database. Real HTTP, signed XPC identity and service startup, live reservations, revocation during a window, sleep/wake, and real hosts cleanup remain unverified. No real hosts file or live credit was used.

## Owner-bound enrollment source

The broker now has an administrator-authorized enrollment operation that verifies the caller's Bloom profile and fetches that profile's enabled macOS website rules before saving the union with the requested domains. It requires an exact server row count and refuses incomplete or invalid rule sets, then checks the administrator grant again immediately before writing. In one broker process, an update or cleanup invalidates an enrollment or access verification that began earlier, preventing that in-flight request from applying afterward. Fixtures exercise wrong peer, revoked authorization, wrong profile, inclusion of a parent-managed domain, truncated server responses, and a stale queued operation. The protocol version is 1.1.17.

This is not connected to the app and is not a complete fallback: parent changes after the enrollment snapshot, multi-process upgrade races, early remote settlement, Hard-mode access, app/account transitions and actual signed XPC and HTTP behavior remain to be addressed or verified. ## Cross-process policy fencing

The broker now captures a root-owned, randomly generated policy revision before an enrollment or access verification goes to the server. Every participating policy change or window installation advances that revision under the same filesystem lock, and the final write checks the captured revision under that lock. The revision remains after cleanup, so an old in-flight enrollment cannot recreate the policy merely because the policy file is absent. A temporary-file fixture performs cleanup in a separate process and rejects an earlier enrollment; it also rejects an earlier access window after cleanup and re-enrollment.

This protects processes running the new implementation. An older installed broker that does not advance the revision is not covered; signed upgrade/rollback and actual service overlap remain unverified. The app-facing fallback, later parent-rule synchronization and hosted migration are still incomplete. No real hosts file was accessed.

## Early access-window close

The broker now has an owner- and session-bound operation to end an Easy hosts window before its deadline. It records the closed session and advances the cross-process policy revision before restoring the saved rules, so an in-flight verification cannot reopen the window and restart reconciliation can finish a close interrupted after the intent was saved. It refuses a different Mac user or a different active session and accepts an idempotent retry. ## Managed hosts-rule refresh source

Owner-bound enrollment now records manual and server-managed domains separately. A new signed-host broker operation verifies the linked profile, fetches the complete current managed website set, and atomically replaces only that portion under the policy revision fence. It preserves manual entries and a valid existing access window; at expiry the latest saved rules are restored. An unchanged snapshot is a no-op, so routine refresh does not invalidate an in-flight access request. Legacy owner-bound policies without separate rule origins return `needsEnrollment` rather than guessing which rules to remove. The protocol version is 1.1.20.

Isolated fixtures cover additions and removals, overlapping manual and managed entries, wrong owners, stale snapshots, an active access window, and interruption after saving a managed update. ## Countdown fallback and close-handle recovery

Website countdown access now checks the account-scoped hosts policy before starting the server countdown. For an enrolled policy, the native bridge keeps the server-returned session ID, records its owner and session in app-group preferences before sending XPC, and asks the root broker to independently verify the existing countdown grant before opening the hosts window. A partial local start rolls back that window. End-access and sign-out close only the matching profile/session window; a lost reply leaves the close handle for retry. The countdown request uses the existing request/device IDs so recovery stays idempotent. Only the profile and server session IDs are persisted for this close path; tokens and device keys remain request-scoped.

The fallback-expected marker is now saved for every known or uncertain policy status, including other-account, pending-cleanup, busy and unsafe. Thus an unavailable broker after a policy observation fails closed. For start requests, `notConfigured` skips fallback; `unavailable` skips only when no prior enrollment intent is recorded. Other policy states fail closed.
